### 1. Forma de trabalhar
- Não avances directamente para a programação.
- Antes de implementar qualquer funcionalidade, explica brevemente o que vamos fazer e porquê.
- Trabalha uma etapa de cada vez.
- Usa linguagem simples e directa, sem explicações técnicas excessivas.
- Não assumas que compreendo todos os conceitos de desenvolvimento.
- Quando introduzires um conceito técnico, explica-o de forma curta.


### 2. Metodologia obrigatória
Para cada funcionalidade, segue esta ordem:

1. Identificar o problema que pretendemos resolver.
2. Definir os requisitos funcionais.
3. Definir os requisitos não funcionais relevantes.
4. Identificar os casos de uso.
5. Verificar o que já existe no projecto.
6. Identificar o que falta ou precisa de correcção.
7. Apresentar a solução proposta.
8. Aguardar a minha aprovação antes de implementar.
9. Implementar e executar os testes.


### 3. Regras importantes
- Não alteres funcionalidades existentes sem explicar o motivo.
- Não cries modelos, campos, métodos ou módulos sem necessidade identificada.
- Não repitas trabalho que já esteja implementado.
- Não elimines dados, bases de dados ou ficheiros sem autorização.
- Respeita as instruções do `AGENTS.md`.
- Consulta a documentação existente antes de tomar decisões.
- Não declares uma funcionalidade concluída sem testes que comprovem o seu funcionamento.

### 4. Como quero acompanhar o trabalho
No final de cada etapa, apresenta apenas:
- O que foi analisado.
- O que foi decidido.
- O que foi implementado, se aplicável.
- Os testes realizados e respectivos resultados.
- O que falta fazer.
- Qual será a próxima etapa.
- Os ficheiros que foram criados ou alterados

Não apresentes grandes relatórios nem avances para várias etapas de uma só vez.

### 5. Primeira tarefa

Não programes nada ainda.

Analisa o estado actual do projecto e ajuda-me a compreender:
- Para que serve esta funcionalidade.
- Quais são os requisitos funcionais essenciais.
- O que já está implementado e o que falta.


Apresenta uma proposta simples e aguarda a minha aprovação antes de continuar.
**O meu objectivo é compreender e acompanhar o desenvolvimento do produto, não apenas receber código pronto.**
